# Phase 45 — UI Design Contract

> Visual and interaction contract for 可用地点覆盖扩展. Generated by gsd-ui-researcher, pending gsd-ui-checker verification.

---

## Phase Scope

Phase 45 does not introduce a new product page, diagnostic dashboard, or large visual surface. It refines the existing Phase 44 map popup and date-dialog entry behavior so places the system recognizes are either clearly saveable or clearly explained as recognized-but-not-saveable.

In scope: `PointSummaryCard` enabled/disabled `留下足迹` states, inline unavailable reason categories, `LeafletMapStage` saveability gating, date dialog opening rules, consistent canonical labels across map/journal/memories, and focused accessibility expectations for disabled CTA + reason text.

Out of scope: dev-only coverage UI, product-facing diagnostic page, new geodata-source ingestion, fallback-region saving, full Playwright visual QA, journal redesign, memories dashboard redesign, favorites, uploads, achievements, or replacing the Phase 44 `FootprintDateDialog`.

## Availability Surface Contract

`PointSummaryCard` remains the only user-facing place availability surface for this phase. It must not become a coverage report.

| State | Popup Contract |
|-------|----------------|
| Saveable authoritative place | Render place name, type pill, subtitle/parent region, and enabled `留下足迹`. Clicking opens the Phase 44 `FootprintDateDialog`. |
| Saved saveable place | Keep the same place-information layout. Show `这里已经留下过足迹` only if already available from Phase 44. CTA label remains `留下足迹`, not `再留一枚足迹`. |
| Recognized but unsaveable | Keep `留下足迹` visible but disabled. Show one inline friendly reason directly above or below the CTA inside the popup detail stack. |
| Fallback explanatory-only place | Show recognized readable place context if available, disabled `留下足迹`, and a friendly reason. Never synthesize save payload fields from fallback lookup. |
| Candidate selection | Keep candidate confirmation separate. Candidate buttons use `确认地点`; no `留下足迹` CTA appears until a candidate becomes a resolved authoritative point. |

Required placement:

- The inline unavailable reason must sit in `PointSummaryCard` near the disabled CTA, not in a tooltip-only affordance and not inside the date dialog.
- The disabled CTA must use real disabled button semantics and retain the hook `data-footprint-cta="true"`.
- The reason container must retain `data-footprint-unavailable-reason` and use `role="note"` or equivalent non-alert semantics.
- The popup must not expose implementation words to users: `boundaryId`, `metadata`, `manifest`, `geometry`, `canonical`, `datasetVersion`, `authoritative`, `frontend_guard`, or `record_authoritative_rejected`.

## Reason Category Contract

Maintain two layers: exact internal technical reasons for tests/logs, and a small stable product-facing category for UI copy.

| Technical Blocking Reason | User Category | UI Copy |
|---------------------------|---------------|---------|
| `missing_boundary_id` | `map_data_unavailable` | `已识别到这个地点，但地图数据还不够完整，暂时不能保存足迹。` |
| `missing_geometry_manifest` | `map_data_unavailable` | `已识别到这个地点，但地图数据还不够完整，暂时不能保存足迹。` |
| `missing_metadata_catalog` | `map_data_unavailable` | `已识别到这个地点，但地图数据还不够完整，暂时不能保存足迹。` |
| `frontend_guard_blocked` | `place_not_precise_enough` | `已识别到这个地点，但还需要更稳定的地点信息才能保存足迹。` |
| `missing_canonical_identity` | `place_not_precise_enough` | `已识别到附近区域，但还不能确认到可保存的具体地点。` |
| `fallback_explanatory_only` | `outside_supported_map` | `这里暂时只能用于查看位置，还不能留下足迹。` |
| `record_authoritative_rejected` | `temporarily_unavailable` | `这个地点暂时还不能保存足迹，请稍后再试。` |
| Unknown/unmapped | `temporarily_unavailable` | `这个地点暂时还不能保存足迹，请稍后再试。` |

Rules:

- UI can render only the `UI Copy` text and, if helpful for tests, a stable non-visible or test-only category value. It must not render the technical reason string.
- Tests must assert the technical reason and mapped category for Phase 45 sample cases.
- Use exactly these four categories in product-facing logic: `map_data_unavailable`, `place_not_precise_enough`, `outside_supported_map`, `temporarily_unavailable`.
- Do not create one-off copy per place. The category copy must remain stable across map popup, focused tests, and future derived surfaces.

## LeafletMapStage Interaction Contract

`LeafletMapStage` must use one shared availability result for CTA state, dialog entry, and unavailable explanation.

| Active Point Type | Required Behavior |
|-------------------|-------------------|
| Saveable authoritative point | CTA enabled; click snapshots the current point and opens `FootprintDateDialog`. |
| Recognized but unsaveable point | CTA disabled; click handler is not invoked; date dialog remains closed; popup explains why inline. |
| Fallback explanatory-only point | CTA disabled; no save payload is created; date dialog remains closed; fallback notice can provide readable location context. |
| Candidate mode | Candidate confirm flow remains active; no date dialog entry until confirmation resolves to a saveable point. |
| Authenticated saved point | Reopening the point uses persisted display labels; CTA remains `留下足迹` if saveability is still true. |
| Anonymous user with saveable point | CTA may be enabled only if existing auth flow handles login before save; no silent failure. If local auth copy is shown, use `登录后才能留下足迹。` |

Implementation-facing contract:

- Replace split boolean checks with a reason-returning predicate such as `getFootprintAvailability(point, manifestState)`.
- The same predicate must decide `PointSummaryCard.isIlluminatable`, `PointSummaryCard` unavailable reason, and `openFootprintDateDialog()` guard.
- If a point lacks any field required for `FootprintPlaceSnapshot`, the CTA must already be disabled before the user can click it.
- `openFootprintDateDialog()` must never fail silently after a visibly enabled CTA click.

## Date Dialog Preservation

Preserve the Phase 44 `FootprintDateDialog` as a standalone controlled sibling of `MapContextPopup`.

| Rule | Contract |
|------|----------|
| Entry | Only a saveable authoritative point may open `FootprintDateDialog`. |
| Snapshot | Build immutable `FootprintPlaceSnapshot` before opening. Submit reads the snapshot, never current active map state. |
| Blocked points | Blocked, fallback, or candidate points must not open the dialog. |
| Submit CTA | Inherit the Phase 44 dialog submit-copy contract; Phase 45 must not introduce a second submit label while changing availability rules. |
| Error | Save failures keep the dialog open and preserve selected date. Use existing error copy unless backend provides a clearer user-safe message. |
| Focus return | On cancel/success, return focus to the triggering `留下足迹` button if enabled; otherwise to stable popup title. |

No Phase 45 UI should invite the user into the date dialog to discover a save-blocking reason later.

## Label Consistency Contract

For newly fixed or newly classified coverage samples, the same canonical display fields must flow through the map popup, saved map highlight, journey journal, and memories stats.

| Field | Source of Truth | Required Consumers |
|-------|-----------------|--------------------|
| `displayName` | Resolved or persisted canonical travel record | Map popup title, date dialog place name, map saved point, journal card title, memories ranking/title |
| `typeLabel` | Canonical metadata / persisted travel record | Popup type pill, date dialog type pill, journal metadata, memories grouping label if shown |
| `parentLabel` | Canonical metadata / persisted travel record | Popup subtitle context, journal region context, memories country/region grouping |
| `subtitle` | Canonical metadata / persisted travel record | Popup supporting text, date dialog supporting text, journal secondary line |
| `boundaryId` | Resolved or persisted authoritative identity | Map highlight lookup only; never user-facing copy |

Rules:

- Do not recompute journal or memories labels from raw coordinates or fallback lookup after saving.
- When a place is fixed to become saveable, verify map highlight uses manifest lookup while user text uses the persisted canonical labels.
- If a blocked point has readable fallback labels, those labels may appear only in the map popup explanation and must not become saved journal/memories data.

## State Feedback Contract

| State | Surface | Copy / Behavior |
|-------|---------|-----------------|
| Recognizing click | Map stage | Keep existing `正在识别地点...` style/status; no new overlay surface. |
| Saveable recognized point | Popup | Enabled `留下足迹`; no unavailable copy. |
| Missing map data | Popup | Disabled CTA; `已识别到这个地点，但地图数据还不够完整，暂时不能保存足迹。` |
| Not precise enough | Popup | Disabled CTA; `已识别到附近区域，但还不能确认到可保存的具体地点。` or stable category copy from table. |
| Outside supported map | Popup | Disabled CTA; `这里暂时只能用于查看位置，还不能留下足迹。` |
| Temporarily unavailable | Popup | Disabled CTA; `这个地点暂时还不能保存足迹，请稍后再试。` |
| Login required | Popup/dialog entry | `登录后才能留下足迹。`; route/open existing auth flow, no silent failure. |
| Save succeeded | Existing page/global notice | `足迹已保存。`; dialog closes and focus returns predictably. |
| Save failed | Dialog + optional page notice | `足迹暂时没有保存成功，请检查网络后重试。`; dialog remains open. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, focus offset, tiny badge/sticker separation |
| sm | 8px | Type pill internals, unavailable reason icon/text gap, compact popup rhythm |
| md | 16px | Popup detail stack, reason block padding, component test target spacing |
| lg | 24px | Popup card padding, map-stage notices, dialog section gaps inherited from Phase 44 |
| xl | 32px | Dialog outer padding and larger map composition gaps inherited from Phase 44 |
| 2xl | 48px | Desktop dialog margins and major map composition gutters |
| 3xl | 64px | Wide desktop map-stage breathing room only |

Exceptions: interactive targets must be at least `44px`; authenticated sidebar width remains `280px`; popup target follows Phase 44 (`320px`, max `384px`, or current fixed high-fidelity popup box); desktop dialog target remains `960px`; no new Phase 45 surface may introduce a larger layout constant.

## Typography

Use exactly these type roles for Phase 45 additions. Letter spacing is `0`.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 600 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading | 24px | 600 | 1.2 |
| Display | 32px | 600 | 1.1 |

Rules:

- Unavailable reasons use Body or Label scale, never Heading/Display.
- Place names remain the strongest popup text; reason copy must not visually compete with the place title.
- Do not introduce weights beyond `400` and `600` in Phase 45-owned UI changes.
- Long place names and reason text wrap without clipping; disabled CTA and reason block must not resize the popup unpredictably.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFF8FD` with `#FAFAFF` | Existing page/map route background, map-stage base, dialog wash |
| Secondary (30%) | `rgba(255, 255, 255, 0.78)`, `#F2E8FF`, `#EAF6FF`, `#FFF0F7` | Popup surface, inline reason wash, disabled CTA background, existing dialog panels |
| Accent (10%) | `#F75A9B` | Enabled `留下足迹`, focus ring, active marker, selected date inherited from Phase 44 |
| Destructive | `#C86464` | Save errors and destructive copy only |

Accent reserved for: enabled popup CTA, enabled dialog submit, selected calendar date, selected shortcut, active/pending marker, focus ring, and one or two small sparkle accents. Do not use accent for disabled unavailable reasons, technical audit labels, or every metadata pill.

Unavailable reasons use muted ink `#6F5B99` on white/lilac/sky soft surfaces, with optional neutral/fallback state color `#B8C6D9`. Error states use destructive only when an attempted save fails, not for a recognized-but-unsaveable explanation.

## Accessibility Contract

| Concern | Contract |
|---------|----------|
| Disabled CTA | Use a real disabled button for blocked points and render adjacent visible reason text. Do not rely on `title` or tooltip alone. |
| Reason text | `data-footprint-unavailable-reason` remains visible DOM text and uses `role="note"` or equivalent. It should be reachable by screen readers in normal reading order near the CTA. |
| Focus | Blocked CTA must not receive an action path into the dialog. If dialog is blocked after state changes, keep focus on the popup title or reason block rather than losing focus. |
| Dialog | Preserve Phase 44 shadcn-vue/Reka Dialog focus trap, Escape behavior, outside close behavior, and focus return. |
| Error announcement | Save failures use `role="alert"` or existing `data-footprint-error="true"` live semantics. Recognized-but-unsaveable explanations are not alerts. |
| Keyboard | Candidate confirmation, enabled CTA, dialog controls, and close buttons remain keyboard reachable with visible focus rings. |
| Decorative images | Popup/dialog decorative assets remain `alt=""` and `aria-hidden="true"`. |
| Reduced motion | Under `prefers-reduced-motion`, marker pulse, hover lift, floating, and breathing effects degrade; disabled/blocked explanation remains readable. |

## Motion Contract

| Motion | Value |
|--------|-------|
| Hover/focus feedback | `140ms` |
| Popup reason reveal | No longer than `180ms`; opacity/transform only |
| Dialog behavior | Preserve Phase 44 `180ms` maximum entrance |
| Hover lift | Max `2px` translate or `1.03` scale |
| Reduced motion | Required; no perpetual pulse when reduced motion is active |

Do not animate `width`, `height`, `top`, `left`, `margin`, or `padding`. The disabled CTA and reason block must not shift layout on hover/focus.

## Forbidden Patterns

- Do not add a dev-only coverage dashboard, product diagnostic page, or new route.
- Do not hide the `留下足迹` CTA for recognized-but-unsaveable detail cards.
- Do not allow blocked/fallback/candidate points to open `FootprintDateDialog`.
- Do not generate save payloads from fallback country/region lookup.
- Do not render internal technical fields or implementation jargon in user-facing copy.
- Do not split CTA enablement and dialog guard into different required-field checks.
- Do not rewrite the Phase 44 date dialog, inline a date form into the popup, or move the dialog inside popup scroll.
- Do not introduce favorites, collections, uploads, achievements, or new navigation entries.
- Do not require full Playwright visual QA for Phase 45 map highlight verification.
