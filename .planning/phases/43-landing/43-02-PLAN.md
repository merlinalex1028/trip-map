<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser route -> auth store | Client route requests rely on restored cookie-session state for UX redirects. |
| auth dialog -> backend auth endpoints | Login/register submit credentials to existing backend endpoints through the auth store. |
| protected route -> backend APIs | Client guard protects navigation only; server guards remain the data boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43-04 | Spoofing | AuthDialog post-success redirect | mitigate | Always use `router.replace('/map')`; do not preserve arbitrary redirect intent or query parameters after auth. |
| T-43-05 | Information Disclosure | Root route restore | mitigate | Await `restoreSession()` before root redirects so authenticated users do not see the public landing flash. |
| T-43-06 | Elevation of Privilege | Protected app routes | mitigate | Set `meta.requiresAuth` on `/map`, `/journal`, and `/memories`; anonymous users return to `/`. Backend `SessionAuthGuard` remains untouched. |
| T-43-07 | Tampering | Old route compatibility | mitigate | Do not keep `/timeline` or `/statistics` compatibility redirects; catch-all routes to `/`, then authenticated root behavior chooses `/map`. |
</threat_model>
