## 地图主舞台视觉

| Option | Description | Selected |
|--------|-------------|----------|
| 高保舞台优先 | 更贴近 `世界足迹.png`，强化柔粉紫、玻璃感、梦幻氛围，同时保留点击与识别清晰度 | ✓ |
| 可读性优先 | 控制装饰强度，优先保证地图本体和边界可读性 | |
| 折中方案 | 氛围明显，但主要把装饰压在外围框架和边缘留白 | |

**User's choice:** 高保舞台优先  
**Notes:** 用户明确要求更靠近高保图整体气质，而不是保守主题化。

---

## 地点弹窗信息层级

| Option | Description | Selected |
|--------|-------------|----------|
| 信息卡优先 | 地点名最突出，其次是类型标签和地区信息，主操作明确但不喧宾夺主 | ✓ |
| 操作优先 | `留下足迹` 最醒目，地点信息退到次级 | |
| 平衡型 | 地点信息与主操作几乎同级 | |

**User's choice:** 信息卡优先  
**Notes:** popup 应该先像精致地点卡，再承载操作。

---

## 日期弹窗结构

| Option | Description | Selected |
|--------|-------------|----------|
| 完整卡片式 Dialog | 独立、存在感明确的对话框，包含地点信息、插画/提示区、快捷日期和日历 | ✓ |
| 轻量快捷弹层 | 更像从按钮延展的轻量面板 | |
| 中等结构 | 是 dialog，但内容更克制、更工具化 | |

**User's choice:** 完整卡片式 Dialog  
**Notes:** 用户希望有明确仪式感，不要退回 popup 内联小表单。

---

## 快捷日期语义

| Option | Description | Selected |
|--------|-------------|----------|
| 单日优先 | 默认理解为“某一天去过”，必要时再补结束日期 | ✓ |
| 区间优先 | 默认就以时间段作为主要心智 | |
| 双模式并列 | 先选单日或区间，再进入具体日期选择 | |

**User's choice:** 单日优先  
**Notes:** 用户更认同“打点记录”而非“默认整段旅行”。

---

## 状态反馈分层

| Option | Description | Selected |
|--------|-------------|----------|
| 分层反馈 | popup / dialog 承接上下文状态，全局 notice 负责成功或更全局错误 | ✓ |
| 全放弹窗内 | 所有状态都在 popup / dialog 内解决 | |
| 全局 notice 优先 | 状态主要通过页面 notice 呈现 | |

**User's choice:** 分层反馈  
**Notes:** 需要清楚但不吵，让当前操作语境尽量留在当前表面。

---

## 已保存地点再次进入交互

| Option | Description | Selected |
|--------|-------------|----------|
| 地点信息卡 + 再次留下足迹入口 | 先展示地点信息和已留下足迹状态，再提供再次新增入口 | ✓ |
| 直接强调再次记录 | 打开后最醒目的是再次记录动作 | |
| 更偏只读 | 主要传达已保存状态，再次新增弱化为次级入口 | |

**User's choice:** 地点信息卡 + 再次留下足迹入口  
**Notes:** 用户不想要历史记录列表，但希望保留温和的重复记录入口。

## 不可保存地点表现

| Option | Description | Selected |
|--------|-------------|----------|
| 禁用主按钮并直接解释原因 | 保留主按钮位置，但禁用并在当前上下文写清原因 | ✓ |
| 主按钮改成说明按钮 | 用替代文案引导用户点开说明 | |
| 保留可点主按钮再拦截 | 点下后在 dialog 中解释不可保存 | |
| 区分多类不可保存 | 根据原因采用不同交互规则 | |

**User's choice:** 禁用主按钮并直接解释原因  
**Notes:** 用户希望用户一眼就懂，不接受“点了才知道不行”。

## Map 页 Sidebar 高保方向

| Option | Description | Selected |

| 视觉微调 | 只做有限视觉修饰，保持当前 Phase 43 shell 味道 | |

## 快捷日期集合

| Option | Description | Selected |
|--------|-------------|----------|
| `今天 / 明天 / 本周末 / 其他日期` | 单日优先下最直接的一组快捷项 | ✓ |
| `今天 / 昨天 / 本周末 / 其他日期` | 偏回顾式记录 | |
| `今天 / 明天 / 昨天 / 其他日期` | 更日常打点，弱化周末语义 | |

**User's choice:** `今天 / 明天 / 本周末 / 其他日期`  
**Notes:** 用户接受以周末作为一个明显旅行语义入口。

---

## 日期 Dialog 首屏结构

| Option | Description | Selected |
|--------|-------------|----------|
| 首屏先地点信息 + 提示区 + 快捷日期，日历在下半区或展开区 | 更像高保图，但层级更分段 | |
| 首屏直接完整显示地点信息 + 快捷日期 + 整个日历 | 信息最完整，直接进入操作 | ✓ |
| 首屏更情绪化展示，日历默认弱化 | 更氛围化，但进入日期选择需要更多一步 | |

**User's choice:** 首屏直接完整显示地点信息 + 快捷日期 + 整个日历  
**Notes:** 用户选择完整首屏，不接受折叠或弱化后的日历出现方式。
