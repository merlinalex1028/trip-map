<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user record notes/tags -> journal card DOM | User-controlled notes and tags render inside the card. |
| journal card -> Pinia record mutation actions | Edit and delete controls cross from UI into persisted record changes. |
| decorative card controls -> user intent | Decorative stars/postcards must not become misleading favorite or upload controls. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-09 | Tampering | `TimelineVisitCard.vue` edit action | mitigate | Preserve `TimelineEditForm` validation and `mapPointsStore.updateRecord()` path; do not add a new edit API path. |
| T-46-10 | Tampering | `TimelineVisitCard.vue` delete action | mitigate | Keep `ConfirmDialog` and `deleteSingleRecord()` confirmation flow with destructive final-record title. |
| T-46-11 | Spoofing | postcard and star/card accents | mitigate | Keep decorative media `aria-hidden`, non-focusable, and free of favorite/upload labels. |
| T-46-12 | Tampering | notes/tags rendering | mitigate | Use Vue interpolation only and assert no `v-html` in the card. |
| T-46-13 | Information Disclosure | card data source | accept | Card renders data already scoped to authenticated store state; route auth is enforced by Plan 46-01. |
</threat_model>
