# Phase 47 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn-vue initialized in `apps/web/components.json` |
| Preset | `style: new-york`, `baseColor: slate`, `cssVariables: true`, Tailwind v4 CSS file `src/style.css` |
| Component library | Existing shadcn-vue local primitives backed by Reka UI 2.9.7 |
| Icon library | Existing `KawaiiIcon` semantic registry over local `@iconify/vue` and `@radix-icons/vue` assets; no runtime network icon fetching |
| Font | `Nunito Variable`, `Noto Sans SC`, `PingFang SC`, `Hiragino Sans GB`, `Microsoft YaHei`, sans-serif |

Sources: `47-CONTEXT.md`, `47-RESEARCH.md`, `apps/web/components.json`, `apps/web/src/styles/tokens.css`, `npx shadcn-vue@latest info` on 2026-05-22.

Phase 47 must extend the existing Yume Kawaii authenticated shell and `/memories` route surface. It must not introduce a second dashboard theme, a public landing composition, or a replacement primitive system.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Chart legend dots, rank metadata gaps, tiny sparkle offsets |
| sm | 8px | Icon and label gaps, rank-row internals, postcard metadata gap |
| md | 16px | Overview card grouping, compact panel internals, mobile grid rhythm |
| lg | 24px | Chart panel padding, dashboard section spacing, desktop card padding |
| xl | 32px | Header-to-overview rhythm and main grid gaps |
| 2xl | 48px | Major dashboard bands and desktop shell breathing room |
| 3xl | 64px | Wide desktop page-level separation only |

Exceptions: Touch targets for empty/error CTAs and any horizontal-strip navigation control must be at least `44px`. Chart canvases reserve a stable panel height through `BaseChart` sizing, and postcard cards reserve fixed aspect-ratio media boxes so labels and scroll state never resize the dashboard grid.

## Typography

Phase 47 dashboard-owned UI uses exactly four sizes and two weights. Existing app-shell tokens may keep inherited values outside this surface.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 24px | 600 | 1.2 |
| Display | 40px | 600 | 1.1 |

Typography rules:

- Overview values, rank counts, and chart-adjacent counts use tabular numeral styling where available.
- Panel headings remain Heading scale. Display scale is reserved for the route title and primary overview numbers, never axis labels, legends, badges, or postcard metadata.
- Chart titles, ranked place names, and postcard place labels wrap or clamp inside their own reserved columns; they never overlay chart canvases or adjacent cards.
- Letter spacing is `0` for Phase 47-owned additions. Do not introduce new uppercase tracking treatments for dashboard labels.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFF8FD` with `#FAFAFF` wash | Dashboard shell background, route-state surfaces, chart stage base |
| Secondary (30%) | `rgba(255,255,255,0.78)`, `#FFF0F7`, `#EAF6FF`, `#F2E8FF` | Glass overview cards, chart panels, rank panel, postcard strip |
| Accent (10%) | `#F75A9B` | Active `/memories` route state, empty-state CTA, focus ring, primary chart emphasis, Top 1 rank accent |
| Supporting chart palette | `#8B6FEF`, `#5EA7F2`, `#7ED9B6`, `#F5A354` | Multi-series chart segments and restrained rank/postcard accents |
| Destructive | `#C86464` | Error copy only; Phase 47 adds no destructive action |

Accent reserved for: the primary empty-state CTA, visible focus rings, active memories navigation cue, monthly trend primary line/fill, one primary donut segment, selected chart emphasis, and the first rank marker. Use supporting chart colors for chart differentiation; do not tint every chart title, card number, rank row, or postcard frame pink.

Color rules:

- Keep the existing deep-indigo ink contract: `#25146F` for strong text and `#6F5B99` for body/support text.
- Charts use the existing Yume Kawaii ECharts theme and very light frame/grid treatment. High-fidelity screenshot colors guide composition only; production values come from real series data.
- Glass backgrounds may use the existing token-backed soft gradients and shadows. Do not add opaque BI-style gray panels or neon chart glow.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `去世界足迹留下足迹` |
| Empty state heading | `还没有留下足迹` |
| Empty state body | `去世界足迹选择真实地点，记录第一段旅途。` |
| Error state | `旅途回忆暂时加载失败，请稍后重试。` Recovery action: `重新加载回忆` |
| Destructive confirmation | `none`: Phase 47 adds no destructive actions |

Additional copy rules:

- Route title is `旅途回忆`. Do not revive user-facing `旅行统计` or `/statistics` vocabulary.
- Overview card labels are `总旅行次数`, `去过地点`, `去过城市或行政区`, and `去过国家/地区`.
- Monthly trend panel title is `旅途足迹趋势`; country panel title is `足迹国家/地区分布`; yearly panel title is `年度旅途趋势`; radar panel title is `旅途回忆画像`; ranking panel title is `热门足迹排行`; postcard band title is `珍藏回忆瞬间`.
- Radar supporting copy must state that the shape is derived from current memories. For sparse-but-valid data use `这是根据现有足迹描出的初始回忆画像。`
- Do not render high-fidelity mockup controls that imply time filtering, achievements, photo upload, expanded leaderboards, journal deep-links, or detail viewers.

## Phase-Specific Visual Contract

Visual authority: `prd/v8.0/UI/旅途回忆.png` defines the dashboard rhythm, chart mix, overview-card cadence, visual Top 5 feel, and postcard-strip atmosphere. Translate it to responsive DOM and real ECharts modules. Do not reproduce its fake chart values, dropdown-like `全部时间` filter, favorite entry, image-viewer implication, or mock style scores that the current travel data cannot explain.

Page composition:

- Keep the authenticated `/memories` route inside the existing shell. The route view remains a state orchestrator and composes focused dashboard sections for overview, charts, ranking, and postcards.
- Header order is route title, one concise support sentence, then four overview cards. Avoid a marketing hero, oversized decorative card stack, or filter toolbar.
- Populated desktop layout uses a wide monthly trend panel paired with the country/region donut panel, then a second row for yearly bars, memories-profile radar, and Top 5 ranking.
- The postcard band sits after charts and ranking as a horizontal browsing strip tied to real recent dated memories. It is not a photo wall or carousel detail entry point.
- Bottom decorative character/scenic assets are optional only when copied from approved v8 assets; they must stay outside chart reading areas and never occlude the postcard strip or rank content.

Overview cards:

- Render exactly four real-data cards for total trips, visited places, visited cities or administrative areas, and visited countries/regions.
- Each card has one label, one dominant value plus unit, and one semantic icon or small decorative illustration in a stable box.
- The city/admin metric may equal place count under the current canonical model when that is the tested aggregate result. Do not invent visual deltas or fake secondary numbers to force the four cards apart.

Chart panels:

- All four required chart families render through `BaseChart`: monthly line, country/region donut-style pie, yearly bar, and radar.
- Monthly and yearly charts visualize trip occurrences from records with usable travel dates. Records without dates must not be bucketed into the current period or `createdAt`.
- Country/region distribution counts trip occurrences, so repeat visits visibly affect segments.
- Radar labels and values must be explainable from current record fields. Use the `旅途回忆画像` title and real-data dimensions selected during planning; unsupported mockup labels such as scenery, culture, or food must not ship as invented scores.
- When the account has trips but a time chart has no usable dated points, keep that panel truthful with an in-panel empty explanation instead of demo series: `这些足迹还没有可用于趋势统计的旅行日期。`

Popular footprint ranking:

- Rank list is fixed to Top 5 and reads as a visual memory list, never a traditional data table.
- Each item foregrounds rank marker, place name, visit count, and most recent visit date. A small deterministic thumbnail or semantic icon may support the place only if it does not compete with the text.
- Sorting semantics are locked by context: repeat visit count first, more recent visit date for ties.
- No `查看更多`, expanded leaderboard, filter, sort control, or row action belongs to Phase 47.

Memory postcard strip:

- Select postcards from real dated travel memories with recent dates preferred. Every visible card carries lightweight place and date context.
- Illustration images are scenic/decorative memory slots, not user uploads. They may reuse or parallel Phase 46 deterministic postcard treatment.
- The strip is browse-only horizontal media. Cards are not journal links, viewer buttons, upload slots, zoom targets, or draggable gallery editors.
- Media images are decorative for accessibility when visible text already exposes place/date context; use empty `alt` text or `aria-hidden` on decorative layers.

## Component Contract

Route and section boundaries:

| Surface | Responsibility |
|---------|----------------|
| `/memories` route view | Preserve auth/restoring/error/empty/populated state orchestration, account-bound stats refresh, and section composition |
| Overview cards section | Present the four typed overview totals and icon/value hierarchy only |
| Chart grid | Build typed chart-panel props/options from real aggregate payloads and render all chart canvases through `BaseChart` |
| Ranking section | Render visual Top 5 order and repeat/recent metadata without fetching independently |
| Postcard strip | Render account-bound postcard seeds as horizontal browse-only cards with deterministic scenic artwork |

Implementation contract:

- Keep stats/session side effects in existing store/service boundaries. Presentational sections receive typed props and do not independently fetch account data.
- Pure chart-option and display derivation helpers may live outside the view when that keeps chart panels testable.
- Use existing local shadcn-vue primitives for reachable focus/scroll/loading behavior where they already fit; use `BaseChart` rather than raw repeated `VChart` configuration.
- Reuse `KawaiiIcon` semantic names or approved local assets. Do not scatter raw Iconify ids or remote images through dashboard sections.

## Interaction Contract

Route states:

| State | Required surface |
|-------|------------------|
| Restoring/loading | Structural Yume Kawaii skeletons for the overview-card row and chart/rank/postcard panel slots; announce restoring status politely |
| Anonymous | Preserve current auth recovery surface with `立即登录`; do not expose fake dashboard values |
| Empty account | Show one honest empty state with the primary CTA to `/map`; omit charts, ranking rows, and postcards |
| Error | Show error copy and `重新加载回忆`; keep recovery non-destructive |
| Populated | Show real overview, chart, Top 5, and postcard sections from current-account data |

Dashboard interactions:

- Chart hover/touch feedback may expose ECharts tooltip values, but panels do not add phase-local filters or data mutation controls.
- Country legend, rank rows, and postcards must not look clickable unless they have an actual Phase 47 action. Postcards remain scroll content, not links.
- Horizontal postcard browsing supports pointer drag/trackpad scroll and keyboard-reachable scroll area semantics when controls are present.
- Loading, empty, error, and sparse-data chart states preserve panel size so the chart grid does not collapse or jump while data resolves.

## Accessibility Contract

- Keep text labels for every chart panel adjacent to the canvas. Canvas visuals are supplemental to panel title, legend labels, values, and surrounding copy.
- Empty, restoring, and error states remain readable as normal DOM text; do not encode state messages inside decorative images.
- Icon-only strip navigation controls, if used, require accessible labels. Decorative chart sparkles, character art, and scenic postcard layers are hidden from assistive tech.
- Focus remains visible against translucent surfaces. CTA and scroll controls preserve at least `44px` interactive targets.
- Ranking order is exposed in DOM reading order with visible rank text/marker; do not rely on color alone to distinguish Top 1.
- Under `prefers-reduced-motion`, hover lift, shimmer, soft floating decoration, and repeated glow motion degrade without hiding chart data or horizontal browsing.

## Responsive Contract

- Mobile collapses dashboard panels to one column and keeps overview cards in a readable single/two-column rhythm only when labels and values fit.
- Chart panels keep stable content height and do not let axis labels overlap legends, titles, or card edges at narrow widths.
- Ranking rows reserve space for place, count, and latest-date metadata before optional thumbnail decoration.
- Postcard strip is the only intentional horizontal overflow in the populated dashboard. The page itself must not gain accidental horizontal scroll.
- Desktop shell spacing follows existing authenticated sidebar constraints; Phase 47 does not redesign navigation width or shell structure.

## Data Integrity Contract

- No chart series, Top 5 row, overview total, or postcard card may be hard-coded as populated dashboard data.
- Dashboard sections reflect current account records or server-authoritative stats and refresh across record edits, deletes, metadata refresh, and auth boundary changes.
- Missing travel dates may still contribute where Phase 47 context allows non-time memories surfaces; they do not enter monthly or yearly buckets.
- Postcard artwork may be deterministic decoration, but postcard selection and visible place/date context must come from real dated record association.
