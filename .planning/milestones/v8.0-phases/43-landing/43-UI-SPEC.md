# Phase 43 — UI Design Contract

> Visual and interaction contract for Landing、登录门禁与应用壳. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Scope

Phase 43 covers the public landing page, the route-level auth gate, the authenticated desktop app shell, and user-facing copy migration for the main route vocabulary.

Desktop high-fidelity is the target. Mobile landing reflow, mobile drawer/bottom navigation, responsive mobile shell behavior, map popup redesign, date dialog redesign, collection UI, travel summaries, badges, progress, and stats inside the sidebar are out of scope.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn-vue initialized in `apps/web/components.json` |
| Preset | `new-york`; Tailwind v4; `baseColor: slate`; CSS variables enabled; `@` alias |
| Component library | Local shadcn-vue primitives backed by `reka-ui` |
| Icon library | `KawaiiIcon` semantic wrapper over locally registered Iconify icons |
| Font | `Nunito Variable`, `Noto Sans SC`, `PingFang SC`, `Hiragino Sans GB`, `Microsoft YaHei`, sans-serif |

Use existing Phase 42 primitives: `Button`, `Card`, `Dialog`, `Popover`, `Calendar`, `Tabs`, `Sidebar`, `Dropdown Menu`, `Skeleton`, `Scroll Area`, `Sheet`, and `Tooltip`.

Do not create a second token system. Use `apps/web/src/styles/tokens.css` and `apps/web/src/style.css` as the theme source, then apply Phase 43 layout-specific CSS in focused landing/shell components.

## Landing Layout

Canonical reference: `prd/v8.0/UI/落地页.png` at `1536 x 1024`. Implement for desktop viewports only and verify at `1366x768`, `1440x900`, `1536x1024`, and `1920x1080`.

| Area | Contract |
|------|----------|
| Root | Full-page public route at `/`, not wrapped in authenticated shell. Use `min-height: 100svh`, `overflow-x: hidden`, and the Yume page background. |
| Stage | Center the design composition. Use a max visual stage of `1536px` content width, while the copied `1672px` scene backgrounds may bleed wider. |
| Hero background | Place `landing-upper-bg.png` as the upper scene. Use `background-size: cover`, `background-position: center top`, and preserve the right-side character/sign composition. |
| Hero DOM block | Left column anchored near the design text area: desktop inline start `clamp(96px, 9vw, 144px)`, top `128px`, max width `560px`. |
| Brand | Top-left brand row at `48px` from top in the design frame; logo `40px`; text `旅记`; subtitle `探索世界 · 记录美好`. |
| Hero title | Two-line display text: `每一次出发，都是与世界的温柔相遇`. Use real DOM, max line width `560px`, no viewport-scaled font. |
| Hero CTAs | Primary `开始记录旅途 ✨` opens register mode. Secondary `探索世界地图 📖` opens login mode because anonymous users cannot enter `/map`. Buttons are `48px` high, pill radius, gap `24px`. |
| Lower section | Use `landing-lower-bg.png` as the lower decorative scene. Overlay real DOM stats, postcard labels if rendered, and bottom CTA panel. |
| Bottom CTA panel | Glass panel width `min(1240px, calc(100vw - 160px))`, height at least `120px`, radius `32px`, centered. Primary `免费注册` opens register mode; secondary `立即登录` opens login mode. |
| Scroll | Full landing may scroll vertically on short desktop heights. Do not collapse into a mobile layout. |

Landing must expose `data-route-view="landing"`, `data-auth-trigger="landing-register"`, `data-auth-trigger="landing-login"`, and `data-auth-trigger="landing-hero-login"` for tests.

## Authenticated Shell Layout

The app shell applies only to authenticated `/map`, `/journal`, and `/memories` routes. It must not appear on `/`.

| Area | Contract |
|------|----------|
| Root | `data-app-shell`, `height: 100svh`, Yume page background, no old topbar navigation. |
| Sidebar provider | Use shadcn-vue `SidebarProvider` with `--sidebar-width: 280px`. |
| Sidebar | Left side only, `collapsible="none"`, `width: 280px`, glass white surface, right border `#E8DDF6`, no mobile drawer work. |
| Brand area | Height `72px`; logo `36px`; brand `旅记`; subtitle `探索世界 · 记录美好`. |
| User card | Avatar `96px`, username only. No level, stars, stats, summaries, badges, progress, or upload control. |
| Navigation | Exactly three entries in this order: `世界足迹` -> `/map`, `旅途手账` -> `/journal`, `旅途回忆` -> `/memories`. Each uses `KawaiiIcon` and Chinese text. |
| Nav item | Height `48px`, horizontal padding `16px`, icon `22px`, gap `8px`, radius `18px`. Current route sets `aria-current="page"` and visual active state. |
| Illustration | One bottom illustration using `sidebar-illustration.png`, width `220px`, decorative alt, fixed across all authenticated routes. |
| Logout | Bottom action label `退出登录`; min height `44px`; routes to `/` after success. No confirmation modal. |
| Main inset | `min-width: 0`, fill remaining width, padding `24px`. Child views keep their own content; Phase 43 only changes route-facing shell/copy. |

Shell must expose `data-shell-sidebar`, `data-shell-nav-item="map"`, `data-shell-nav-item="journal"`, `data-shell-nav-item="memories"`, and `data-shell-logout` for tests.

## Interaction Contract

| Interaction | Contract |
|-------------|----------|
| Initial root visit while restoring | Show a short restore state: `正在恢复你的旅途...`; do not flash landing to authenticated users. |
| Authenticated `/` | Redirect to `/map` after session restore resolves. |
| Anonymous protected routes | `/map`, `/journal`, and `/memories` redirect to `/`; do not auto-open login and do not show a login-required warning. |
| Login/register success | Always navigate to `/map`; do not preserve redirect intent. |
| Logout success | Navigate to `/`; existing lightweight global notice may remain if visually unobtrusive. |
| Landing register triggers | `开始记录旅途 ✨` and `免费注册` call `openAuthModal('register')`. |
| Landing login triggers | `探索世界地图 📖` and `立即登录` call `openAuthModal('login')`. |
| Sidebar active route | Active nav item uses accent wash, deep ink text, and `aria-current="page"`. |
| Motion | Use `--motion-quick: 140ms` and `--motion-emphasis: 180ms`. Hover lift max `2px`; no long decorative animation required. |
| Reduced motion | Under `prefers-reduced-motion`, disable floating/breathing/lift transitions; keep color/focus states. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, focus offset, tiny decorative separation |
| sm | 8px | Compact element spacing, sidebar inner rhythm |
| md | 16px | Default element spacing, button horizontal padding unit |
| lg | 24px | Shell padding, CTA gaps, section internal spacing |
| xl | 32px | Landing panel padding, major card gaps |
| 2xl | 48px | Brand offset, hero CTA block spacing, large top/bottom breathing room |
| 3xl | 64px | Page-level section breaks |

Exceptions: interactive targets must be at least `44px`; landing visual stage uses the fixed `1536 x 1024` reference ratio; authenticated sidebar width is fixed at `280px`; default avatar is `96px`.

## Typography

Use exactly these Phase 43 type roles for new landing/shell surfaces. Letter spacing is `0`.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 24px | 600 | 1.2 |
| Display | 40px | 600 | 1.1 |

Do not use viewport-scaled font sizes for Phase 43 landing/shell text. Do not introduce weights beyond `400` and `600` in new Phase 43 components, even though older tokens contain heavier display weights.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFF8FD` with `#FAFAFF` | Page background, landing lower field, app content base |
| Secondary (30%) | `rgba(255, 255, 255, 0.78)`, `#F2E8FF`, `#EAF6FF` | Sidebar, glass panels, secondary CTA, soft nav states |
| Accent (10%) | `#F75A9B` | Primary CTA fill, active nav marker/wash, auth trigger emphasis, focus ring |
| Destructive | `#C86464` | Logout error text and destructive-state affordances only |

Accent reserved for: landing primary CTA, bottom `免费注册` CTA, active sidebar item, selected/focused auth trigger, focus ring, and small sparkle accents. Do not apply accent to every link, every icon, or all body text.

Use supporting colors sparingly: `#5EA7F2` for secondary blue details, `#8B6FEF` for deep purple emphasis, `#7ED9B6` for mint decorative badges, and `#F5A354` for warm decorative stats/icons. Primary text is `#25146F`; muted text is `#6F5B99`.

## Accessibility Contract

| Concern | Contract |
|---------|----------|
| Semantic text | Landing headings, CTA labels, nav labels, username, restore text, empty states, and errors are real DOM text. |
| Decorative images | Scene backgrounds and sidebar illustration use `alt=""` and `aria-hidden="true"`. Default avatar uses `alt="默认头像"` unless username-specific alt is provided. |
| Buttons and links | CTA triggers are `<button type="button">`; sidebar entries are `RouterLink`; logout is a button. |
| Focus | Visible focus ring: `2px solid #F75A9B`, offset `4px`; focus must not be clipped by rounded containers. |
| Keyboard order | Landing: brand is not focusable, hero CTAs, bottom CTAs, auth dialog. Shell: nav entries, logout, then route content. |
| Active nav | Current route sets `aria-current="page"` and does not rely on color alone. |
| Auth dialog | Reuse existing `AuthDialog`; preserve focus trap, Escape close, submit error announcement, and focus return. |
| Contrast | Deep ink `#25146F` on light surfaces for primary text; muted text `#6F5B99` only on white/glass surfaces. |

## Forbidden Patterns

- Do not put the landing page inside the authenticated shell.
- Do not preserve redirect intent after login/register; always route to `/map`.
- Do not add compatibility redirects for `/timeline` or `/statistics`.
- Do not show `我的收藏`, collection icons, future placeholders, upload avatar controls, sidebar stats, level, star count, badges, travel summaries, or progress.
- Do not keep `AuthTopbarControl` as the primary authenticated navigation surface.
- Do not use a full page screenshot as the interactive UI.
- Do not count baked PNG text as accessible product copy.
- Do not reference `prd/v8.0/切图/...` paths directly from Vue.
- Do not implement mobile drawer, bottom nav, or mobile landing reflow in Phase 43.
- Do not rename broad files solely for naming purity.
