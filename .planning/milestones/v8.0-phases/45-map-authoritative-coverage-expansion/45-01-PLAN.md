<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client coordinates -> `/places/resolve` | Untrusted latitude/longitude enter canonical place resolution. |
| geometry manifest -> metadata catalog | Static geometry/metadata assets become canonical identity used by save and replay paths. |
| fallback failed resolve -> frontend explanation | Failed `OUTSIDE_SUPPORTED_DATA` responses may still produce readable frontend fallback labels, but not save payloads. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-01-01 | Tampering | `phase45-coverage-cases.ts` saveable samples | mitigate | Matrix validates catalog-derived `placeId`/`boundaryId` and canonical resolve asserts metadata lookup by both ids before later save tests. |
| T-45-01-02 | Tampering | fallback `OUTSIDE_SUPPORTED_DATA` sample | mitigate | Resolve e2e asserts failed fallback has no `place`; later plans must keep `fallback_explanatory_only` disabled. |
| T-45-01-03 | Information Disclosure | test failure output | accept | Failure output includes canonical ids and blocking reasons only in test logs; no user PII or session data is present. |
| T-45-01-04 | Denial of Service | coverage audit scope | mitigate | Matrix contains focused real runtime samples only; no full manifest scanner or generated geodata process is introduced. |
</threat_model>
