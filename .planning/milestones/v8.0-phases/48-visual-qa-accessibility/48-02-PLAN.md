<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Keyboard user -> auth dialog | Keyboard input and focus state cross into the auth modal and must remain observable. |
| Router state -> sidebar | Current route state determines visual and accessible navigation state. |
| QA fixes -> auth/session behavior | Accessibility fixes must not weaken login, register, logout, or route guard behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-48-05 | Spoofing | `AuthDialog.vue` | mitigate | Do not bypass `useAuthSessionStore()` or change login/register success routing while fixing focus/labels. |
| T-48-06 | Tampering | `ShellSidebar.vue` | mitigate | Keep nav model limited to `map`, `journal`, `memories`; tests must fail if extra destinations return. |
| T-48-07 | Denial of Service | keyboard flow | mitigate | Focus close/open paths must not leave `document.activeElement` on `body` for the core path. |
| T-48-08 | Information Disclosure | auth error status | accept | Error messages remain generic and do not reveal whether an email exists. |
| T-48-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs are allowed in this plan. |
</threat_model>
