# Feature Landscape — v8.0 Yume Kawaii 视觉重构与登录地图体验

**研究日期:** 2026-05-09  
**输入资料:** `8.0/prompt.md`、`世界足迹.png`、`旅途回忆.png`、`旅途手帐.png`、`留下足迹.png`、新增 `落地页.png`  
**用户确认:** 纳入设计图中除收藏功能外的其他能力；旅途手账不提供“添加新旅行”入口。

## 设计图拆解

### 落地页

设计图新增了未登录首屏：
- 顶部品牌“旅记”和 tagline
- 大幅插画/旅行背景 hero
- 主标题“每一次出发，都是与世界的温柔相遇”
- 主 CTA“开始记录旅途”
- 次 CTA“探索世界地图”
- 四个功能卡：点亮世界地图、旅途时间轴、旅行图鉴、成就与徽章
- 数据信任区：国家/地区、旅行者、足迹点亮、用户好评
- 回忆照片卡片
- 底部注册/登录 CTA

v8.0 范围解释：
- 必须实现未登录落地页和登录按钮。
- “旅行图鉴”“成就与徽章”本轮作为展示/视觉卡片，不实现真实收藏、徽章系统或图鉴数据模型。
- “开始记录旅途”和“立即登录”应打开注册/登录；登录成功后进入地图。
- “探索世界地图”未登录时也不进入真实地图，应引导登录或打开 auth modal。

### 世界足迹（地图页）

设计图要求：
- 登录后应用壳有左侧导航、用户卡片、底部插画
- 主区域为淡粉紫中国/世界地图
- 地点标记改为星形/发光 marker
- 地图点击后 popup 显示“识别结果”、地点名称、类型标签、地区信息和“留下足迹”
- 底部有提示条“点击地图上的星标，识别地点并留下你的旅行足迹吧”

v8.0 范围解释：
- 当前 Leaflet 地图保留，视觉层改造。
- 弹窗不再直接内嵌日期表单；点击“留下足迹”打开独立日期弹窗。
- 已保存地点仍应展示地点信息和过往记录，但主 CTA 文案使用“留下足迹/再留一次足迹”。

### 留下足迹（日期弹窗）

设计图要求：
- 独立大弹窗，左侧地点信息和插画，右侧日历
- 快捷选择：今天、明天、本周末、选择其他日期
- CTA“留下足迹”
- 关闭、取消、提交行为清晰

v8.0 范围解释：
- 必须从地图 popup 中抽离日期选择，成为 modal。
- 日历/日期选择优先使用 UI 库 DatePicker；如果无法满足高保图，再使用专用 datepicker。
- 数据仍写入现有 `CreateTravelRecordRequest.startDate/endDate`，不新增旅途内容模型。

### 旅途手账

设计图要求：
- 独立页面，左侧导航一致
- 标题“旅途手账”
- 发光渐变竖线、星形节点
- 旅行卡片带日期、地点、地区、描述、图片缩略图
- 卡片右侧的收藏心形按钮来自设计图，但用户确认收藏功能不纳入

v8.0 范围解释：
- 不提供“添加新旅行”入口。
- 不实现收藏按钮/收藏状态。
- 图片缩略图本轮作为视觉缩略图/插画位，不能暗示用户上传照片能力。
- 记录仍来自地图“留下足迹”。

### 旅途回忆

设计图要求：
- 独立 Dashboard 页面
- 四个概览卡：总旅行次数、去过地点、去过城市、去过国家/地区
- 趋势折线图、国家/地区环图、年度柱状图、风格雷达图、热门足迹排行、回忆图片横滑
- 顶部时间范围筛选

v8.0 范围解释：
- 应实现真实可用的统计 dashboard，不再只有 3 张 StatCard。
- 当前后端 `TravelStatsResponse` 只有 `totalTrips`、`uniquePlaces`、`visitedCountries`、`totalSupportedCountries`，不足以支撑所有图表。
- 可用前端 `travelRecords` 派生月度/年度趋势、热门地点排行、国家分布；如果需要 server-authoritative，则扩展 `/records/stats` contract。
- “累计天数”未在当前数据模型中可靠存在：可以由已知 start/end date 的记录派生，未知日期不计入，并明确文案。

## Table Stakes

| 类别 | Requirement-level feature | 说明 |
|---|---|---|
| 登录入口 | 未登录用户先看到落地页 | `/` 未登录显示 landing，不挂载真实地图 |
| 登录门禁 | 后续应用页面都需要登录 | 地图、旅途手账、旅途回忆均需要 authenticated |
| 应用壳 | 左侧导航替代当前 topbar 主导航 | 已登录主应用使用固定/响应式侧栏 |
| 文案 | 点亮/旅行统计/时间轴替换 | 全路径文案统一为留下足迹/旅途回忆/旅途手账 |
| 地图弹窗 | 始终显示地点信息 + 留下足迹 | 不在 popup 内直接展开日期表单 |
| 日期弹窗 | 独立 modal 选择日期 | 支持日历和快捷日期 |
| 覆盖扩展 | 可识别地点尽量可保存 | 需要处理 boundaryId 缺失、unsupported fallback |
| 手账 | 发光时间线与旅行卡片 | 不提供添加新旅行入口 |
| 回忆 | 图表化 dashboard | 使用成熟图表库，不手写复杂图表 |

## Differentiators

| Feature | 价值 | 实现建议 |
|---|---|---|
| Yume Kawaii 高保视觉 | 让产品从工程 demo 升级为完整情绪化体验 | 统一 token + UI 库主题 overrides + 自定义插画区域 |
| 星形地图标记与节点呼吸 | 增强“留下足迹”的仪式感 | CSS keyframes + Leaflet marker class |
| 旅途回忆多图表 | 让数据页面有探索价值 | ECharts 主题化 |
| 落地页故事感 | 未登录前提供价值说明和转化入口 | 独立 `LandingPageView` |
| 应用壳统一导航 | 地图/手账/回忆有一致 IA | `AppShell` + route meta |

## Explicitly Out of Scope

| 不做 | 原因 |
|---|---|
| 收藏功能 | 用户明确排除，包括我的收藏、爱心/星标收藏按钮与状态管理 |
| 旅途手账“添加新旅行”入口 | 用户明确排除；创建仍从地图真实地点开始 |
| 用户上传照片 | 会引入存储、上传、安全和内容管理，超出 v8.0 |
| 真实成就/徽章系统 | 设计图可展示，但不做数据模型和解锁规则 |
| 社交/公开主页 | 与单用户私密地图主线不符 |
| 全球城市级统一覆盖 | 范围过大；v8.0 只做“当前可识别地点尽量可用”的可落地闭环 |

## 功能优先级

1. **先门禁和壳层**：落地页、登录后 AppShell、路由守卫。
2. **再核心地图交互**：文案、popup、独立日期弹窗、可用性扩展。
3. **再页面视觉升级**：旅途手账、旅途回忆。
4. **最后视觉 QA**：桌面/移动截图、图表渲染、Leaflet 非空、弹窗不遮挡。

## 关键开放点

- UI 库最终选 Naive UI 还是 Element Plus，需要在执行前定稿。研究推荐 Naive UI，Element Plus 作为稳妥备选。
- 旅途回忆图表数据是否必须全部 server-authoritative？如果是，需要扩展 stats contract；如果接受前端派生，可更快落地。
- 落地页插画素材如何交付：本轮可先使用设计图风格的本地 CSS/图片占位，后续再替换成正式素材。
